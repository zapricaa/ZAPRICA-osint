Product Requirements Document (PRD): ZAPRICA
(Enterprise AI OSINT Platform)
1. Product Overview & Vision
The transition from manual Open-Source Intelligence (OSINT) gathering to automated, AI-driven investigations represents a paradigm shift in cybersecurity. Traditional platforms aggregate data via strict API integrations, leaving the cognitive burden of pivoting, hypothesis generation, and correlation entirely to the human analyst.
ZAPRICA is a B2B enterprise-grade, autonomous AI OSINT investigation platform. It addresses the intelligence gap by deploying reasoning agents capable of operating authorized web browsers and shell environments to conduct multi-step investigations autonomously. The product vision is to shift the analyst's role from manual data gathering to strategic decision-making by utilizing agents that guarantee evidence provenance and mitigate enterprise security risks.
2. Target Audience & User Personas
Security Operations Center (SOC) Analysts (Tier 2/3): Need to rapidly triage and enrich indicators of compromise (IOCs) without manually bouncing between dozen tabs and APIs.
Cyber Threat Intelligence (CTI) Teams: Require automated mapping of threat actor infrastructure across the open web and dark web.
Digital Forensics & Incident Response (DFIR) Consultants: Need auditable, provenanced evidence collection that holds up to legal scrutiny.
Authorized Penetration Testers: Require automated, safe reconnaissance of target infrastructure.
3. Problem Statement & Competitive Landscape
The cybersecurity threat intelligence market features legacy link-analysis tools, automated scanners, and emerging AI copilots. Existing products exhibit significant gaps in autonomous, non-API-dependent investigation capabilities.

4. Functional Requirements
4.1 The Execution Orchestrator
Requirement: The system must support long-running, multi-step investigations that survive transient network failures or backend crashes.
Implementation: The architecture must utilize Durable Execution (Temporal.io + LangGraph). LangGraph maps the stateful agent loops, while Temporal.io orchestrates the workflows, ensuring state persistence during rate-limit pauses or deep recursive searches11.
4.2 The Browser Agent Worker
Requirement: The system must navigate dynamic web pages autonomously when APIs are unavailable.
Implementation: ZAPRICA will utilize a browser agent orchestrated by the browser-use Python library running on Playwright14.
Context Pruning: To prevent LLM context-window exhaustion, the system will use an Accessibility Tree extraction strategy rather than passing raw HTML. The agent focuses on interactive elements, using unique IDs to issue commands17.
Human-in-the-Loop (HITL): If the agent encounters a CAPTCHA, Temporal.io must automatically pause execution and present a HITL interface for analyst intervention16.
4.3 The Shell Agent Sandbox
Requirement: The agent must safely execute required command-line utilities (e.g., nmap, whois) without risking host compromise.
Implementation: All shell execution must be routed into ephemeral Docker containers running with read-only filesystems. Strict seccomp (secure computing mode) profiles must filter and drop dangerous system calls, limiting execve to an authorized whitelist19.
4.4 Tool Registry
Requirement: The platform must support a standardized plugin architecture for expanding OSINT capabilities.
Implementation: ZAPRICA will integrate tools using the Model Context Protocol (MCP). The backend will expose available modules using JSON-RPC 2.0 messages (such as tools/list and tools/call)21.
4.5 Knowledge Graph & Entity Resolution
Requirement: The system must store intelligence findings recursively and ensure no duplicate entities are created.
Implementation: ZAPRICA will utilize PostgreSQL combined with the Apache AGE extension. This provides openCypher graph querying capabilities directly within PostgreSQL, avoiding the infrastructure overhead of a standalone Neo4j cluster for the MVP27.
Provenance: Every finding must be cryptographically anchored. The evidence schema will store the entity, source URL, an ISO 8601 timestamp, an S3 object pointer for the raw screenshot/HTML, and a SHA-256 hash.
5. Non-Functional Requirements (Security & Privacy)
5.1 Security & Threat Mitigation
ZAPRICA must mitigate the OWASP Top 10 for LLM Applications (2025/2026)30.
Defending Against Indirect Prompt Injection (LLM01): To prevent compromised web pages from hijacking the agent32, ZAPRICA will implement the Dual LLM (DualView) Pattern34.
Privileged Planner LLM: Holds instructions and tool privileges but cannot read raw, untrusted external web data.
Quarantined Extractor LLM: Reads raw web page content but possesses zero tool-calling capabilities; it is constrained to outputting structured JSON.
Defending Against Excessive Agency (LLM06): Mitigated through strict validation of JSON-RPC parameters in the MCP Tool Registry38.
5.2 Privacy & Legal Compliance
Note: Subject to legal counsel review.
The system must comply with the Indian Digital Personal Data Protection (DPDP) Act, 2023. Specifically, it leverages Section 3(c)(ii), which exempts personal data made publicly available voluntarily by the Data Principal or under a legal obligation39.
Controls: The platform must enforce an Authorized-Use Policy (digital attestations per case), immutable audit logging, and automated data purging policies.
6. Business Model & Pricing
ZAPRICA will operate on a Hybrid Enterprise Model (Platform Fee + Capacity):
A fixed annual platform fee grants access to the software, RBAC, data segregation, and baseline user seats.
Customers receive a baseline allocation of "Agent Compute Hours."
Additional intensive autonomous investigations are billed in bulk API tiers to protect vendor margins against variable LLM inference costs.
7. Development Roadmap & Milestones
Phase 1 (MVP - Months 1-2): FastAPI backend, LangGraph state machine, MCP Tool Registry, PostgreSQL + Apache AGE database, DualView security architecture. (Goal: Hackathon demo and angel pitching).
Phase 2 (Seed Stage - Months 3-8): Migrate state orchestration entirely to Temporal.io for durable execution. Implement Kubernetes horizontal pod autoscaling for Browser Workers. Complete SOC2 readiness assessments.
Phase 3 (Series A - Months 9-18): Full microservices architecture. Implement Kong API Gateway for advanced rate-limiting, SAML/SSO integrations, and integrate egress proxy networks with rotating IPs. Establish official channel partnerships with threat intelligence feeds.
