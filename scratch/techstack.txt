ZAPRICA: Technology Stack Blueprint
(Enterprise AI OSINT Platform)
1. Introduction
This document outlines the core technology stack for ZAPRICA, an enterprise-grade autonomous AI OSINT platform. The stack is specifically engineered to support long-running agent workflows, execute isolated sandbox processes, parse dynamic web applications, and protect the system against adversarial prompt injection attacks.
2. Frontend & User Interface
The presentation layer prioritizes real-time updates and interactive graph visualization for analysts.
Core Framework: React and Next.js (utilizing Server-Side Rendering for fast initial loads and secure routing).
Graph Visualization: react-force-graph (WebGL-accelerated rendering).
Justification: Cybersecurity intelligence graphs often contain thousands of nodes (IPs, domains, hashes). WebGL rendering ensures the browser does not crash during complex OSINT investigations.
State Management: Zustand (for lightweight, fast client-side state management without the boilerplate of Redux).
3. Backend API & Microservices
The backend acts as the gateway and tool provider for the autonomous agent.
Web Framework: FastAPI (Python 3.11+).
Justification: Provides high-performance, asynchronous REST APIs natively built on OpenAPI and Pydantic validation.
Tool Integration Standard: Model Context Protocol (MCP) utilizing JSON-RPC 2.01.
Justification: Standardizes how the AI connects to external OSINT tools using tools/list and tools/call schemas, abstracting the tool execution logic away from the core LLM prompt4.
4. Agent Orchestration & State Management
Managing the state of an autonomous loop is the most complex engineering challenge in the platform.
Agent State Machine: LangGraph.
Justification: Defines the Node/Edge logic of the autonomous investigation loop (Plan -> Execute -> Extract -> Graph), mapping exactly how the LLM transitions between decisions.
Durable Execution Orchestrator: Temporal.io.
Justification: LangGraph alone cannot reliably handle tasks that take hours (e.g., waiting out an API rate limit). Temporal.io orchestrates the LangGraph workflows as durable executions, ensuring that if a worker crashes or a network times out, the exact state of the investigation is preserved and resumed automatically7.
5. Isolated Execution Workers
Execution is heavily decoupled into isolated workers to ensure security and prevent the main event loop from blocking.
5.1 Browser Agent Worker
Technology: browser-use (Python library) combined with Playwright (Chromium)10.
Design Pattern: Accessibility Tree Extraction.
Justification: Instead of passing raw, token-heavy HTML to the LLM, browser-use extracts a simplified DOM accessibility tree. It assigns unique IDs to interactive elements, allowing the LLM to issue precise commands (e.g., clicking or typing) without expensive vision processing or context exhaustion.
5.2 Shell Agent Sandbox
Technology: Docker Engine and Linux seccomp.
Design Pattern: Ephemeral Sandboxing.
Justification: The LLM is never given direct host-shell access. Tool requests spin up a single-use Docker container with a read-only filesystem13. A custom seccomp profile severely restricts kernel system calls, explicitly filtering execve to a whitelist of safe OSINT binaries (e.g., whois, dig)14.
6. Database & Evidence Storage
The database must handle traditional relational data (users, auth) and complex graph traversals (intelligence relationships) simultaneously.
Primary Database: PostgreSQL 16+.
Graph Engine: Apache AGE (PostgreSQL Extension).
Justification: Provides openCypher graph querying capabilities directly within PostgreSQL15. This eliminates the need to run and synchronize a separate Neo4j cluster, vastly simplifying MVP deployment while retaining deep recursive query capabilities.
Evidence Blob Storage: AWS S3 (or MinIO for self-hosted instances).
Justification: Stores raw, cryptographically hashed evidence (screenshots, HTML DOMs, stdout logs) linked directly to the edges in the Apache AGE graph to guarantee investigative provenance.
7. AI Model Layer (Security & Logic)
To defend against Indirect Prompt Injection (IPI), ZAPRICA implements the Dual LLM (DualView) pattern18.
The Privileged Planner LLM: (e.g., Anthropic Claude 3.5 Sonnet / OpenAI GPT-4o).
Role: Orchestrates the investigation, accesses tools via MCP, and determines pivoting logic. Strictly quarantined from reading raw, untrusted web data.
The Quarantined Extractor LLM: (e.g., Meta Llama-3-8B / GPT-4o-mini).
Role: Processes raw HTML or tool output. It has zero tool-calling privileges and is strictly constrained to outputting structured JSON entities. This sanitizes malicious data before it reaches the Planner, neutralizing web-based prompt injections.
8. Infrastructure & Deployment
Container Orchestration: Kubernetes (Amazon EKS / Google GKE).
Justification: Required for horizontal pod autoscaling, particularly for dynamically spinning up intensive Playwright browser worker pods based on queue depth.
API Gateway & Rate Limiting: Kong API Gateway.
Justification: Manages strict tenant rate-limiting and access control policies for B2B enterprise customers.
Egress Network: Rotating Residential Proxy Networks.
Justification: Required for the browser workers to navigate target domains without being immediately blocked by basic anti-bot web application firewalls (WAFs).
